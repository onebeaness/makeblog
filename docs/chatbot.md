# 리뷰 챗봇 (챕터 10)

상품 리뷰 100건을 근거로 답하는 RAG 챗봇. `/chat` 에 있다.

블로그(챕터 09)와 같은 앱 안에 있지만 서로 아무것도 공유하지 않는다.
로그인도 필요 없다 — 누가 쓰든 답은 같으므로 인증이 검증할 것이 없다.

---

## 챕터 09 와 결정적으로 다른 점

**서버 전용 비밀 키가 처음 생긴다.**

| | 챕터 09 블로그 | 챕터 10 챗봇 |
| --- | --- | --- |
| 키 | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `PINECONE_API_KEY`, `ANTHROPIC_API_KEY` |
| 브라우저 노출 | **해도 됨** | **절대 안 됨** |
| 왜 | RLS 가 방어선 | 지켜줄 것이 없음 — 노출되면 남이 내 크레딧을 씀 |
| 그래서 구조가 | Server Component 만으로 충분 | **API Route 를 반드시 거침** |

```
브라우저 → /api/chat (서버) → Pinecone · Anthropic
                ↑ 키는 여기서만 존재. 브라우저는 절대 못 봄
```

이 표가 아키텍처를 결정한다. 명세 02절이 말한 그대로다.

---

## 명세대로 하지 않은 곳 세 군데

### 1. 임베딩을 갈아끼울 수 있게 만들었다 — 명세 02절의 모순 때문

명세는 임베딩을 **Ollama 로컬**(RTX 4070)로 못박았다. 그런데 그러면
**배포가 불가능하다.** `OLLAMA_BASE_URL=http://localhost:11434` 에서
`localhost` 는 배포된 서버 입장에서 *그 서버 자신*이지 당신 PC 가 아니다.

명세는 로컬 실행을 전제하고, 완료 기준(09절)은 배포를 전제한다. 둘이 안 맞는다.

그래서 `EMBEDDING_PROVIDER` 하나로 갈리게 했다.

| 값 | 임베딩 | 어디서 도는가 | 03절 모델 비교 |
| --- | --- | --- | --- |
| `pinecone` (기본) | `llama-text-embed-v2` (무료) | 로컬 · 배포 둘 다 | 불가 |
| `ollama` | `qwen3-embedding:0.6b` 등 | 로컬만 | **가능** |

명세 02절이 LangChain 을 고른 이유가 "모델 교체를 한 줄로"였다.
그것을 임베딩에도 적용한 것뿐이다.

### 2. 페이지를 `/` 가 아니라 `/chat` 에 두었다

명세 07절은 "페이지는 `/` 하나"라고 했다. 그런데 거기엔 이미 챕터 09 블로그가 있다.
같은 앱에 얹으면 새로 만들 인프라가 Pinecone 하나뿐이다 —
수파베이스도 배포도 이미 돌아가고 있으므로.

### 3. 엔드포인트에 `retrieveOnly` 를 붙였다

명세 05절은 엔드포인트 두 개(`/api/index`, `/api/chat`)를 정했다. 그것은 지켰다.
대신 `/api/chat` 이 `{ question, retrieveOnly: true }` 를 받으면
**LLM 을 부르지 않고 검색 결과만** 돌려준다.

명세 08절 3단계가 "LLM 없이 검색된 리뷰 5건만 화면에 나열"하라고 하면서
*건너뛰지 말 것*이라고 강조한 그 단계다. 한 번 하고 지우는 대신 상시 기능으로 남겼다.
화면의 **"검색만 보기"** 체크박스가 이것이고, 평가 스크립트도 이 경로를 쓴다
(15문항에 LLM 을 부르지 않으니 요금이 들지 않는다).

## 시작하기

### 1. 수파베이스에 리뷰 원문 넣기

SQL Editor 에서 순서대로 실행한다.

```
supabase/migrations/0002_reviews.sql   테이블 + RLS (조회만 허용)
supabase/seed_reviews.sql              리뷰 100건
```

`reviews` 에는 **조회 정책 하나만** 있다. 쓰기 정책이 없으므로 브라우저에서는
아무도 쓸 수 없다. 인덱싱은 서버에서만 일어난다.

> 인덱싱을 `service_role` 키로 넣는 길도 있지만 이 저장소는 그러지 않는다.
> 리뷰는 한 번 넣고 끝인 정적 데이터인데, 그것 때문에 RLS 를 통째로
> 우회하는 만능 키를 서버에 두는 것은 위험 대비 이득이 없다.

### 2. Pinecone

[pinecone.io](https://www.pinecone.io) 무료 가입 → API 키 복사.
인덱스는 `/api/index` 가 없으면 자동으로 만든다 (1024차원 · cosine).

### 3. LLM 키

Claude 를 쓴다면 [console.anthropic.com](https://console.anthropic.com) 에서
API 키를 만들고 **크레딧을 충전**한다.

> ⚠️ **Claude Pro 구독과 API 요금은 별개다.** 구독 중이어도 API 는 따로 결제한다.
> Grok 도 마찬가지다.

기본 모델은 `claude-opus-5` 다. 더 싼 모델을 쓰려면 `LLM_MODEL` 로 바꾼다
(예: `claude-haiku-4-5`). 어느 쪽이든 요금은 실제 사용한 토큰만큼 나간다.

### 4. 환경 변수

`.env.local.example` 의 챕터 10 구역을 `.env.local` 에 복사해 채운다.
배포한다면 호스팅 서비스의 Environment Variables 에도 같은 값을 넣는다.

### 5. 인덱싱 → 질문

```bash
npm run dev
```

`/chat` → **샘플 인덱싱** 버튼 → `완료 — 100건` 이 뜨면 성공.
그다음 질문한다.

## 랭체인 5단계가 어디에 있는가

| # | 단계 | 이 프로젝트에서 | 파일 |
| --- | --- | --- | --- |
| 1 | Document Loaders | CSV 100건 읽기 | `src/lib/rag/reviews.ts` |
| 2 | Text Splitters | **사실상 무동작** — 리뷰 1건 = 청크 1개 | — |
| 3 | Embedding Models | 텍스트 → 1024차원 벡터 | `src/lib/rag/embeddings.ts` |
| 4 | Vector Stores | Pinecone 업서트 · 검색 | `src/lib/rag/pinecone.ts` |
| 5 | Retrievers | 가까운 리뷰 top-5 회수 | `src/lib/rag/chain.ts` |

2단계가 이번에 무동작인 이유는 리뷰 한 건이 이미 짧아서다.
긴 PDF 로 RAG 를 만들면 **거기서 품질이 갈린다** — 문장 중간에서 자르면
그 조각의 벡터가 엉뚱한 좌표를 갖고, 검색이 통째로 무너진다.

LCEL 은 유닉스 파이프와 같은 발상이다.

```
Prompt | Model | OutputParser
(리뷰를 템플릿에 끼우고) → (LLM 에 보내고) → (텍스트만 뽑는다)
```

## 임베딩 모델 비교 (명세 03절)

벤치마크 점수가 아니라 **내 리뷰 100건에서의 성능**으로 고른다.

```bash
# 1) .env.local 에서 임베딩 모델을 정하고
# 2) /chat 에서 샘플 인덱싱
# 3) 평가
npm run dev          # 다른 터미널
npm run eval
```

```
Recall@5   86.7%   (13/15)
MRR        0.712
기록: eval/results/qwen3-embedding-0-6b.json
```

모델을 바꿔 인덱싱을 다시 하고 또 재면, 결과가 네임스페이스별로 따로 쌓인다.

| 지표 | 뜻 | 왜 이걸 보나 |
| --- | --- | --- |
| **Recall@5** | 상위 5건 안에 정답 리뷰가 하나라도 들어왔는가 | LLM 에 5건만 넘긴다. 그 안에 없으면 답은 **반드시** 틀린다 |
| MRR | 첫 정답이 몇 번째로 나왔는가 (1/순위) | 5건 안에는 들어왔는데 5등인지 1등인지 |

평가셋은 `eval/questions.json` — 질문 15개와, 각 질문의 정답 리뷰 ID를 사람이 직접 표기했다.

> **검색이 놓친 정보는 LLM 이 절대 복구하지 못한다.**
> RAG 품질의 상한선은 검색이 결정한다. 답변이 부실할 때 프롬프트부터
> 고치는 것은 대개 잘못된 순서다.
>
> 차이가 거의 없게 나와도 유효한 결론이다. 100건 규모에서는 모델 선택이
> 병목이 아니라는 뜻이며, 그렇다면 설치가 간단한 쪽이 승자다.

## 완료 기준 (명세 09절)

- [ ] "운동할 때 써도 되나요?" 에 운동·러닝 리뷰가 top-5 안에 들어온다
- [ ] 답변에 인용된 내용이 실제 출처 리뷰에 존재한다 (환각 없음)
- [ ] **리뷰에 없는 내용을 물으면 모른다고 답한다**
- [ ] 개발자도구 Network 탭에 API 키가 보이지 않는다
- [ ] 두 임베딩 모델의 Recall@5 수치가 기록되어 있다

세 번째가 가장 중요하다. RAG 의 목적은 아는 것을 잘 답하는 게 아니라
**모르는 것을 지어내지 않는 것**이다. 프롬프트(`src/lib/rag/prompt.ts`)에
그렇게 적어야 지켜진다.

시험해 볼 질문: **"이 이어폰 방수 등급이 IPX 몇이에요?"**
리뷰에 등급 숫자를 말한 사람이 없으므로 "찾지 못했습니다"가 정답이다.
